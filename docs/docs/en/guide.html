Overview and file types

Instant Video & Picture Search Pro manages a local SQLite search index for supported videos, images, TXT files and directories. Search uses saved names, paths and metadata. Directories support scope selection and limited search context; results show supported files.

A previously indexed drive can also be searched offline using its saved entries. Opening files and file operations still require an accessible file and a safe drive assignment.

Video extensions: .3gp, .avi, .divx, .flv, .m2ts, .m4v, .mkv, .mov, .mp4, .mpeg, .mpg, .mts, .rm, .rmvb, .ts, .vob, .webm, .wmv, .xvid.
Image extensions: .bmp, .gif, .jpeg, .jpg, .png, .tif, .tiff, .webp.
Other supported extension: .txt.

A supported extension does not guarantee readable duration or dimensions. TXT is indexed by filename/path, not by text content. There is no image-subject, face, regular-expression or full-text content search. Not every format is fully analysed.

FFprobe sources and SHA-256 checksums are available in the download section.

First steps

  1. Start the application. The main window opens while the saved database is checked. Database ready means ready to search, not fully indexed.
  1. Check the database and drives. If the saved file is missing, explicitly open an existing index database or create a new one under File. A missing file alone never creates a replacement database. When changing an already loaded database, follow the displayed restart notice.
  1. Open Index → Set indexing targets. Add only the accessible drives or folders you want and check recursion.
  2. Choose Start indexing, inspect the actual target preview and explicitly confirm starting.
  3. Wait for completion and check errors and completeness status.
  1. For searching, use drive buttons or Select search folders.
  2. Enter a query and additional/media filters if needed; results update as you type.
  3. Open a matching file or show its folder in Windows Explorer.

Indexing reads real directories and stores file information. An index update reconciles those targets again and reuses unchanged metadata. Normal search reads existing index entries and does not start a full scan. Normal application startup does not promise automatic full indexing; deliberately enabled automatic updating is a separate setting.

Search, filters and results

Main search combines terms with AND. With or:, positive terms are alternatives. holiday -beach finds holiday and excludes beach from the name and path. "summer holiday" matches one continuous phrase in a single field. film -"making of" excludes the phrase. or: holiday beach -trailer requires at least one alternative and also excludes trailer.

The additional filter supports exclusions and phrases. Its positive terms always use AND, and or: is not an operator here. A leading minus attached to a term or phrase excludes it. A minus on its own and hyphens within a term are literal. Use "-holiday" to match a literal leading minus. Empty fields add no condition. Exclusions alone filter the chosen search locations. Incomplete or empty phrases and more than 200 terms per field return no results.

The search matches substrings in filenames and stored paths. Outside quotes, % matches any sequence and _ matches one character. Inside a phrase, both are literal. Case matching follows existing SQLite rules. Advanced main queries use direct results only.

Search filters groups file size, video duration and image dimensions. Images and TXT files have separate display toggles. Groups wrap in narrow windows, and the upper controls can be scrolled.

The File size from and File size to fields are individually optional and include the endpoints. Select MB or GB as the shared unit. A blank field leaves that limit open. Both fields blank disables size filtering. Decimal values can use a comma or decimal point. The upper bound must be at least as large as the lower bound. Width and height are independent minimums in pixels. Video duration uses minutes, seconds and a tolerance in seconds.

Show images controls search display. Include images when indexing separately controls whether a new indexing run includes images. Supported videos and TXT remain in the format allowlist. Folders and arbitrary unsupported formats are not shown as normal file results.

The X buttons clear their respective text fields. Editing the main or additional query keeps the other filters and search locations. Reset filters clears the size bounds, width, height, duration and tolerance and restores MB as the size unit. It retains both queries, the image and TXT switches and the search locations.

The list shows up to 1,000 rows per page. Show more results and Back change the page. Additional batches are loaded from the index on demand. Shown refers to the current page and loaded to the current batch. More direct results available means another direct result was found. The app does not calculate an exact total for this display. Paging also reaches direct matches beyond the previous loading limit.

Click Name, Size, Duration, Resolution, Date or Path to sort all matching direct results. Click again to reverse the order. An arrow marks the active direction. Missing values appear last. Resolution uses pixel count. The sort remains active when the query changes. Use Search → Sort by relevance to return to the default ranking. It retains the existing ranking within each batch and may add up to 1,200 folder results in the first batch. Column sorting includes direct results only.

Open files using the result action; the folder action shows their location in Windows Explorer. An offline index entry may remain visible even when its file cannot be opened. The context menu also contains real file operations such as moving, renaming and deleting: these can change media and are separate from normal search. Use them deliberately and read the displayed prompts.

History and favorites belong to the active database. Select an entry at the top to reuse its main query. The favorite star or Search → Save current main search as favorite saves only the main text, not a complete search profile with additional/media filters. Empty queries are not saved; saving again does not create a duplicate. Remove one entry using its bin button; delete all only from the Search menu with confirmation. History is limited to 25 entries.

A simple favorite saves only the main query. In Search, choose “Save current search as a profile…” to save the additional query, size range, duration, image dimensions, image and TXT switches and search locations as well. A profile may have an empty main query. “Load search profile…” restores the settings and runs one search. “Manage search profiles…” lets you load, rename or confirm deletion of a profile. Profiles belong to the active database. Drive scopes use confirmed collection identities and can still be searched offline. The app reports missing collections or folders when loading.

Drive selection and identification

Drive buttons allow multiple selection. All selects available buttons; None clears the quick selection and yields no results in that mode. Buttons can be selected even without a loaded database; this does not invent indexed results.

For connected drives, blue indicates a whole-drive search scope. Amber indicates a partial scope. Saved drives appear in a separate collapsible group. A known name is shown without the historical drive letter. In the dark theme, lighter teal and a prominent border indicate the actual selection. Keyboard focus has its own subtle color. Clicking does not leave a bright border when the collection is unselected. Tooltips retain the historical assignment and known top-level folders.

A drive button, All or None activates drive search. Saved custom search folders are retained but do not additionally restrict the quick selection. Select search folders and Apply reactivate your custom selection.

Startup and Refresh drives apply the same check to the actual drive path. If Windows clearly reports a missing, not ready or unusable filesystem there, the drive letter is excluded from Connected drives after discovery. A volume ID alone does not make the drive path usable. An empty, valid filesystem still appears. A usable drive appears again after remounting. The list includes only drive letters for which Windows confirms a valid filesystem and root directory. Inconclusive results, such as access denied or a timeout, keep the drive out of the regular list until it is confirmed again. Saved indexes and search selections remain available. Folder-mounted volumes can still be selected as search folders or indexing targets.

Search folders and recursion

The tree shows Available drives, Indexed drives currently disconnected and Not currently checked / availability unclear. Available is based on a confirmed current identity. Not checked or an identity conflict does not prove that a drive was unplugged. Available drives are ordered by their confirmed current mount.

An arrow expands a branch; only then are its directly indexed subfolders loaded. A checkbox selects a search scope. These actions are separate. Multiple drives/folders can remain open and selected. Load more folders appends a limited batch under that parent. Some intermediate nodes support navigation only and cannot be individually selected without their own folder entry.

Selected scopes appear on the right. X removes only that scope from the local dialog selection. Clear selection empties it; an empty custom selection yields no results. All drives in the dialog returns to the tree overview without clearing selection. Apply saves; Cancel or closing the window discards dialog changes.

Include subfolders on: files in the selected folder and its indexed subfolders are included. Muted child ticks indicate inherited coverage and do not create extra saved individual scopes. Amber ancestors indicate partial selection. Without recursion, only files directly in the selected folder count. An explicitly selected entire indexed drive remains fully included.

Multiple selected scopes combine with OR; overlap does not duplicate results. Selecting an entire drive already includes an additionally ticked folder, so this creates no exclusion. Additional text, format and media filters can still exclude every match.

Show hidden and system folders affects tree display, not index deletion or search filtering. Known system/cache names are hidden by default; attributes are checked in a limited way only with a confirmed accessible assignment. Not all attributes can be established offline. Already saved hidden scopes remain on the right and in the filter. Reopen levels after toggling.

The selection is saved separately for each database. Historical paths remain available for offline navigation; missing or conflicting identities are not automatically repaired. Selecting search folders starts neither indexing nor cleanup.

Indexing targets and target preview

Search folders determine which existing index entries are searched. Indexing targets determine which real drives/folders an explicitly started job reads. The selections are independent; a search folder is not a hidden indexing target.

Index → Set indexing targets: add a folder/drive, choose its root for an entire drive, or remove individual targets. Include subfolders controls recursive reconciliation; without it, only immediate entries are processed. Apply saves indexing selection; Cancel discards changes and starts no job.

Start indexing or Reconcile index targets invokes the existing checks. The preview shows the actual resolved paths, scope/recursion and existing indexed data. A missing/ambiguous identity never simply selects a different drive with the same letter. Confirm only after checking; Cancel starts nothing. An empty target selection does not mean an unrestricted full scan.

Partial-scope runs clean up only safely completed selected scopes. They do not claim a complete index of the entire drive and block the unsuitable global follow-up cleanup. To update existing entries, explicitly reconcile the same desired targets again.

Indexing actions and updates

Start indexing and Reconcile index targets use the same basic scope-indexing flow with saved targets and a preview. A repeat run is not a different fast-scan algorithm. Directories are traversed again; saved metadata can be reused when modification time and size are unchanged. Entire subtrees are not skipped merely because a parent folder is unchanged.

Index / update selected drives is a separate flow for explicitly chosen whole quick-selection roots; check its preview and start confirmation too. Quick-selection buttons alone do not start such a run.

Refresh drive display and the top Refresh drives action update the existing device display, not a requested full index. Detection alone does not make a device indexed. A confirmed assignment and actual saved index entries are separate facts.

Stop indexing requests cancellation. Already saved partial results may remain; cancellation is not a complete finish and does not trigger global deletion of missing entries. Access/parser errors can make a run incomplete; an analysis error does not automatically mean a damaged file.

Under Index maintenance, startup maintenance and periodic maintenance can be enabled separately. Periodic options are 1, 2, 3, 6, 12, 24, 48, 72 and 168 hours, plus Custom for any whole number from 1 to 168. The default is 24 hours. Saving the interval does not start indexing. The next scheduled check uses the new value and considers due time, confirmed accessible drives and saved targets. Accessing a due drive can wake it from standby.

Index progress, timer and errors

The main status shows the current step and distinguishes completion, partial completion, cancellation and failure. The detail line shows the available counts for checked files, files saved to the index, scan errors, analysis errors and path conflicts. Waiting indexing jobs are shown separately from preparation. A status note appears if automatic maintenance is deferred for the current drive observation.

The compact indexing status shows the operation, target and current step. It also shows counts for checked files, new files and errors, plus files per second once enough data has been measured. Open the status line for further run details.

When the total is unknown, the progress bar indicates activity. Percentages require a verified total. A rough remaining time may be shown when a comparable index baseline and sufficiently stable throughput are available. Otherwise the scanning phase shows “Estimating remaining time”. There is no additional full file count.

Scan errors concern traversal or file access; analysis errors concern metadata extraction. Missing information, parser errors and timeouts are possible. Without specific log evidence, neither the exact cause nor damaged files are proven. Check error details or existing measurement logs; do not infer a need for an automatic repair run.

Incomplete can result from scan/analysis errors, conflicts or unfinished processing; manual cancellation is handled separately. Already saved entries can still be searchable. A partial scope additionally remains partial and does not prove a complete drive index.

The local measurement log is at %LOCALAPPDATA%/ExplorerSuche/index_runs.jsonl. It records job/scope times and counters, not a full list of all failed files. At most 256 KiB per file plus one previous generation; rotation may remove older measurements. It is neither a database backup nor a full diagnosis of error causes.

Database, indexed files and drive status

DATABASE shows loading/ready/error state, selected file and size. Ready means the index is available for search, not proof of a complete scan of every drive. If the file is missing, old results are not presented as current matches.

INDEXED FILES shows saved total, video, image and folder counts. Files and folders are separate counters. DRIVES shows related indexed data and current or historical states. The separate search-results display distinguishes visible/loaded rows and possible further direct matches.

Detected and confirmed: the current drive is uniquely assigned. Not currently checked: there is no reliable current accessibility evidence yet. Not currently found: the completed observation found no confirmed current drive. Status not documented: historical run data is missing; this means neither empty nor complete. A previously complete run does not prove the current state.

A current mount is today's mounting path, such as a drive letter or directory mount. A historical mount is a saved earlier path. The internal owner/drive identity distinguishes indexed data independently of the visible name. Identical names/letters do not prove identity.

Details opens the structured indexed-data dialog. The last complete run appears only if reliably documented; otherwise it is unknown. Technical details show identities, historical/current mounts and run data when needed. Displaying this loaded information does not repair or index anything.

Maintenance, assignments and backups

Use maintenance only for a specific reason. The current menu has no additional harmless Check index button: search diagnosis and the extended self-test have different effects. The following describes actual available actions, not automatic repair recommendations.

Diagnose search results and filters …
Open Index maintenance → Check search and filters … to review terms, media filters, search locations, sort column and direction, the loaded batch, visible results and the availability of more results. The diagnosis uses a matching result or a bounded read-only query with existing drive observations. Folder context is limited to the first relevance batch.

Index self-test / possible path correction …
Purpose: Checks database access and samples; with a confirmed identity it may correct saved paths and then clean up index entries.
When: Use only for a specific assignment/index problem, not as a harmless read-only test.
Data access: Write test with rollback; permanent index path correction and cleanup within the scope are possible.
Media files: No changes to media files.
Protection / Confirmation: Has its own confirmation prompt. Path correction and deletion use the existing identity checks and verified-backup rules; ambiguous assignments remain blocked.

Database information / Details
Purpose: Shows the path, size, counts, drive states and optional technical identities from already loaded information.
When: To identify the active database or understand historical indexed data.
Data access: Read-only display; opening the dialog does not start repair or indexing.
Media files: No changes.
Protection / Confirmation: No confirmation or backup required; unknown values remain visibly unknown.

Index → Drive status / assignment …
Purpose: Compares detected drives with saved identities. Check and confirm assignment saves an explicit binding.
When: When a unique automatic identification is unavailable. Do not confirm based on the same drive letter alone.
Data access: The overview reads state; a confirmed binding writes a database-specific settings file without rewriting index entries yet.
Media files: No change. The separate marker action does create an identity file on the selected drive.
Protection / Confirmation: Binding and creating a marker have separate explicit confirmations and renewed identity checks. No automatic marker creation. Confirmation does not retrospectively prove a complete indexing run.

Repair saved drive paths …
Purpose: Corrects stored absolute index paths after a uniquely confirmed mount change.
When: When the same drive is mounted elsewhere and path correction is necessary.
Data access: May permanently change index paths. Ambiguous historical entries are not guessed or assigned to another drive.
Media files: Does not change or move media files.
Protection / Confirmation: Yes/No confirmation, identity verification and a verified backup in the existing path-correction flow. No corresponding rewrite if backup fails.

Index cleanup / Clean invalid index entries
Purpose: Checks a time- and count-limited sample of selected accessible indexed drives for paths confirmed to no longer exist.
When: After deliberately removing files, if stale results are distracting. A brief cleanup does not prove that the entire index is complete.
Data access: May delete index rows; not read-only.
Media files: Does not delete media files.
Protection / Confirmation: The button or menu item starts without another Yes/No prompt. Before actual deletion: a verified backup, identity/accessibility checks and a transaction. Ambiguous/locked drives are retained. Nothing is deleted without a successful backup. Existing rules may also permit limited idle cleanup; partial-scope protection remains authoritative.

Reset selected indexed drives / Clear the entire active media index
Purpose: Removes selected indexed drives or all media index entries from the active database.
When: Only for an intentional fresh start, not for normal updates.
Data access: Permanently deletes index entries, not the database file. History, favorites and settings are retained.
Media files: No changes to media files.
Protection / Confirmation: The scope/path is confirmed; clearing everything requires a second confirmation. Verified manual backup, database identity, locks and a transaction; errors abort the operation.

Backups and recovery
Use File → Back up database now … to save a verified SQLite snapshot to a location of your choice. It includes index entries, offline collections, history, favorites and search profiles. It does not copy your pictures or videos. Database backups … lists files in the backup folder. The app checks a selected file only on request.
Choose File → Restore database from backup … to select and verify a backup. The app creates a new file after confirmation and keeps existing files. If a database is already loaded, a separately confirmed switch takes effect after restarting the application.
New manual backups include the separate database-specific search locations, indexing targets and interval settings. Older backups can only restore settings they contain. Restore does not establish drive bindings. Existing automatic backups and rotation continue to retain up to five recent generations within 30 days and protect the newest verified backup. Manual backups are outside this rotation.

Frequently asked questions

Why no results?
Check the loaded database and search locations. Check search and filters … shows the active conditions and whether more direct results are available. An offline collection can be searched when its entries are in the active database.

Why disconnected or a different letter?
A drive may be unplugged, locked or mounted elsewhere. The application distinguishes historical paths from current confirmed identities. Unclear accessibility does not prove offline status. Do not confirm a manual binding merely because a name/letter matches.

Why incomplete?
Scan/analysis errors, conflicts or cancellation can prevent complete processing. Saved results often remain usable. Check existing error details first; a new full scan or cleanup is not automatically required.

Why missing duration or resolution?
A supported file type may lack the information or be unreadable by the parser; access and timeouts can also matter. Establish a cause only from available evidence. Active width/height filters can therefore exclude such image entries.

Why no remaining time?
The estimate needs a comparable baseline and usable throughput measurements. While the current scan lacks enough data, the activity indicator is still available.

Why an old drive in the search tree?
Its saved index is useful offline. Displaying it implies neither current accessibility nor a new assignment.

Why confirm targets before indexing?
Search folders and real indexing targets are independent. The preview shows the paths and recursion the job will actually process.

How to keep the database safe?
Normal search does not change media; real file operations are separate. Close the application before making your own file backup, back up the database and important external media separately, verify the backup and retain originals. Read the actual effect of risky maintenance first. There is no absolute data-safety guarantee.

Data safety and limitations

The index stores file information, not complete copies of your media. Search, indexing and real file operations are separate activities. Normal search does not reanalyse every medium on each keystroke or change media files; history/favorites may be saved in the database.

Existing identity checks aim to prevent operations on the wrong volume. They replace neither your own checks for manual assignment nor backups. Copied markers provide no cryptographic authenticity guarantee. A locked or disconnected drive must not be cleaned up merely because access is unavailable.

Deleting index maintenance follows existing verified-backup, identity and transaction rules. Not every display or write test makes a backup. Automatic backups are tied to particular operations, not a promised regular all-purpose backup. Read notices and confirmations; an earlier successful test does not guarantee a future without errors.

German and English describe the same features and safety rules. Change the language in Settings; search and indexing state are preserved. User filenames, paths and drive names are not translated. Close and reopen native file pickers or message boxes already on screen if needed. Help and QR resources are local; donations remain voluntary and do not open a website.

Change overview for version 1.0.18

Ten seconds after startup, the application checks available drives and existing search indexes once more. If the database or a drive check is still loading, it waits for that operation to finish. In safe startup, existing indexes can be searched on explicitly selected drives whose identities are confirmed.

The application automatically saves its position, size and normal or maximized state. It restores them on the next start. If the previous monitor is unavailable, the window opens on an available work area. Minimizing or hiding to the notification area retains the last visible placement.

This guide covers version 1.0.18. An unusable path is excluded from the connected list even if a volume ID exists. In the dark theme, the actual selection of saved drives is visually distinct from keyboard focus.

Local search over supported media/TXT filenames and paths, saved sizes/dimensions/durations, additional text and a limited paged result display.

Multi-drive selection and hierarchical custom search folders with recursive, inherited and partial states; separate real indexing targets with a preview.

Search history and saved favorites, incremental reconciliation reusing unchanged metadata, identity-based recognition of drives whose mounts change.

Three status cards with structured technical details, a separate result status, live indexing timer and a limited local measurement log; unknown total size remains explicitly unknown.

Light/dark themes, clearer drive markings and search-tree groups, understandable indexing/maintenance actions and central help and version information.

Protected index cleanup and clearing with verified backups, transactions and identity checks. No general automatic recovery or absolute safety guarantee.

The manual update check in the Help menu fetches the public version manifest over HTTPS and reports whether a newer version is available. Use the link it offers to open the release page.
